## 1. Objetivo
Que `docker compose up` levante `db`, `api` (NestJS con `/api/health`) y `web` (nginx con proxy) desde un clon limpio.

## 2. Qué hizo el agente
- Comprobó la DoR (sin dependencias) y registró el inicio en la bitácora (B-32).
- Raíz: `.gitattributes` (`* text=auto eol=lf` y binarios), `.dockerignore`, `.gitignore` (agrega `*.tsbuildinfo`) y `docker-compose.yml` con `db`, `api` y `web`, healthchecks, `depends_on: condition: service_healthy` y todas las variables con `${VAR:-valor}` (las de Postgres y las 11 del spec §5).
- `src/api`: NestJS 12 con prefijo global `/api`, `HealthModule` con `GET /api/health` → `{"status":"ok"}` (no consulta la base), ESLint (flat config con typescript-eslint), Jest + ts-jest con un test del health y `Dockerfile` en tres etapas (`build`, `deps` solo producción y `runtime` con `USER node`).
- `src/web`: Vite 8 + React 19 + TypeScript + Tailwind 4 (plugin de Vite), página placeholder sin estilos de diseño, ESLint (react-hooks, react-refresh) y `Dockerfile` en dos etapas (`node:24-alpine` compila y `nginx:1.30-alpine` sirve). `nginx.conf` escucha en 8080 (IPv4 e IPv6), hace proxy de `/api/` → `api:3000` y tiene fallback de SPA a `index.html`.
- Versiones exactas en ambos `package.json` y `package-lock.json` generados con `npm install --save-exact`.
- Ejecutó la verificación completa del backlog, el lint, el test y `docker compose up -d --build`.

## 6. Desvíos del plan
- **TypeScript 6.0.3 en lugar de la 7.0.2 (latest):** typescript-eslint 8.72.2 admite `typescript <6.1.0` y ts-jest 29.4.15 `<7`. Se fija la última 6.0.x en api y web.
- **Script `test` de la API con `--experimental-vm-modules`:** NestJS 12 se publica solo como ESM y Jest en modo CommonJS no lo carga (`Must use import to load ES Module: …@nestjs/testing/index.js`). El script ejecuta `node --experimental-vm-modules --no-warnings=ExperimentalWarning node_modules/jest/bin/jest.js`. La API compila a CommonJS y en ejecución carga Nest con el `require(esm)` nativo de Node 24, sin flags. Se activó `isolatedModules: true` porque ts-jest lo pide con `module: nodenext` (aviso TS151002).
- **Build de la API con `tsc` en vez de `@nestjs/cli`:** el CLI no es necesario para compilar y evita una dependencia más.
- **Test unitario del health:** no estaba pedido en T01. Se agregó para que `npm --prefix src/api test` (convención del backlog) tenga algo que correr desde el inicio.

## 7. Ambigüedades encontradas
- **Versión de NestJS:** el spec dice "NestJS" sin versión. Se usó la última (12.5.0), que es ESM-only. Si más adelante Prisma, Jest o algún paquete de Nest da problemas con ESM, la opción conservadora sería bajar a NestJS 11 (CommonJS). Queda a decisión de la persona.
- **`DATABASE_URL`:** no está en la tabla de parámetros del spec §5 y el health de T01 no usa la base, así que no se declaró. Lo agrega T02 junto con Prisma.
- **`NODE_ENV` y `PORT` en `api`:** no están en el spec §5. Se fijaron `production` y `3000` en el compose (sin `${VAR:-…}` porque no son configurables por el usuario). El puerto 3000 lo marca el spec §10.
- **Etiqueta de nginx:** el spec no la fija; se usó `nginx:1.30-alpine` (rama estable).
