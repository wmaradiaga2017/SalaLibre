## 1. Objetivo
Que la persona inicie sesión, vea la navegación según su rol y que las rutas queden protegidas.

## 2. Qué hizo el agente
- Instaló con versión exacta TanStack Query, React Router, React Hook Form, Zod y el resolver de Zod (ver §6).
- `shared/apiClient.ts`: único cliente HTTP. Usa `fetch` con `credentials: 'include'` y prefijo `/api`, y convierte
  `{ error: { code, message, requestId } }` en `ApiError` (`status`, `code`, `message`, `requestId`). Cuando el cuerpo
  no es JSON, toma el `requestId` del header `X-Request-Id`; un fallo de red da `NETWORK_ERROR`. Todo 401 llama al
  manejador que registra `AuthProvider`, salvo en las tres llamadas de sesión, que lo resuelven ellas mismas
  (`skipUnauthorizedHandler`). El 409 `BOOKING_CONFLICT` usa el mensaje de F-02 ("Ese horario acaba de ocuparse.").
- `shared/queryClient.ts`: no reintenta los 4xx; los errores de red o 5xx se reintentan una vez.
- `features/auth/`:
  - `authService` (login, logout y `me`; `me` devuelve `null` ante un 401).
  - `AuthProvider` (consulta `['auth','me']`). Atiende los 401: vacía la caché salvo la sesión, la deja en `null` y
    navega a `/login`.
  - `auth-context.ts` (`useAuth`, separado del componente por `react-refresh`).
  - `LoginPage` sencilla, con logo y textos del prototipo.
  - `LoginForm` (RHF + Zod; props `onFocusChange`, `onPasswordVisibleChange` y `onSubmitStatusChange` para T07c).
  - `PasswordField` (alterna `type`, `aria-pressed` y el nombre "Mostrar contraseña"/"Ocultar contraseña").
  - `ProtectedRoute` (cargando: spinner; error de `/me`: `ErrorState` con `requestId` y "Reintentar"; sin sesión:
    `/login`), `RequireRole` y `ForbiddenPage`.
  - `SessionLayout`: une la sesión con el layout y define los enlaces por rol.
- `shared/layout/`:
  - `AppLayout`: barra superior con logo, navegación por rol (`NavLink`, se desplaza en horizontal dentro de la
    barra en anchos pequeños), enlace "Saltar al contenido" y `<main>`.
  - `UserMenu`: avatar, nombre y rol; panel con "Mi cuenta" y "Cerrar sesión" que se cierra con Escape o al hacer
    clic fuera.
  - `PlaceholderPage`: marcador de las pantallas futuras.
- `App.tsx`: `QueryClientProvider` → `BrowserRouter` → `AuthProvider` → `ToastProvider` (montado aquí, como pedía
  T07a), con las rutas de spec §9:
  - `/` redirige a `/agenda`.
  - `/admin/*` va dentro de `RequireRole role="ADMIN"`.
  - Una ruta desconocida redirige a `/agenda`.
- Se comprobó todo en el navegador contra el compose (§5).

## 6. Desvíos del plan
- **Dependencias nuevas** (versión exacta). Las tres primeras están en D-01:
  - `@tanstack/react-query` 5.107.1
  - `react-hook-form` 7.92.0
  - `zod` 4.6.7
  - `react-router` 8.5.1: D-01 no nombra un router, pero la tarea pide "Router con las rutas de spec §9". Es el
    router estándar de React y su versión 8 admite React 19.3.
  - `@hookform/resolvers` 7.0.6: el adaptador oficial que une React Hook Form con Zod (D-01).
- `npm audit` informa una vulnerabilidad moderada de `minimatch`, que llega por `typescript-eslint` (dependencia de
  desarrollo previa a esta tarea, no entra en la imagen). No se tocó: la corrección propuesta baja `typescript-eslint`
  con un cambio incompatible.
- **Menú de usuario como "disclosure"** (botón con `aria-expanded` y un panel con enlaces), no como `role="menu"`, que
  exige navegación con flechas. Es accesible por Tab y se cierra con Escape.
- **Se agregó "Saltar al contenido"** al layout (spec §11, navegación por teclado).
- En la primera versión, el nombre accesible del botón del menú repetía nombre y rol. Se corrigió antes de cerrar
  (`sr-only sm:not-sr-only`) y se volvió a comprobar.

## 7. Ambigüedades encontradas
- **CA6 y el manejador general de 401:** hoy la única petición protegida es `GET /auth/me`, que trata el 401 como "sin
  sesión" y devuelve `null` (la ruta lleva a `/login`). El manejador del `apiClient` para las demás peticiones está
  listo, pero no se pudo ejercitar en el navegador sin una pantalla que llame a la API. Se probará con T07b y T08.
- **Destino tras el login:** siempre `/agenda`, como dice F-01, aunque se haya llegado a `/login` desde otra ruta (no se
  recuerda la ruta de origen). Es la opción más conservadora.
- **`/login` con sesión válida** redirige a `/agenda`. El spec no lo dice; se evita mostrar un login inútil.
- **Rutas desconocidas y `/admin` a secas** redirigen a `/agenda` (con sesión) o a `/login` (sin sesión). El spec no
  define una pantalla 404.
- **Correo con espacios en los extremos:** el formulario los quita antes de validar y enviar, como hace la API
  (`normalizeEmail`). La contraseña se envía tal cual.
- **Errores del login que no son 401** (red, 5xx): se muestra el mensaje del `apiClient` con su `requestId` en el
  mismo banner.
- **Textos de `LoginPage`:** se usaron los del prototipo ("Acceso a SalaLibre", "Bienvenido de nuevo", "Inicia sesión
  para gestionar tus reservas de salas."). El enlace "¿Olvidaste tu contraseña?" y la composición de dos columnas
  quedan para T07c.
- **Revalidación de la sesión:** `/me` se considera fresca durante 60 s. Después, TanStack Query la vuelve a pedir al
  recuperar el foco de la ventana, y una sesión vencida (RN-19) lleva a `/login`.
