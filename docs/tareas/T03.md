## 1. Objetivo
Iniciar y cerrar sesión con cookie `httpOnly`, consultar el usuario actual y proteger toda la API con denegación por defecto.

## 2. Qué hizo el agente
- **Módulo `users` mínimo:**
  - Dominio puro en `domain/`: tipos `Role`, `PublicUser` y `UserWithCredentials`, `toPublicUser` y `normalizeEmail` (RN-23).
  - Interfaz `UsersRepository` con el token `USERS_REPOSITORY`, e implementación `PrismaUsersRepository` con `findByEmail` y `findById`. `findById` devuelve `null` si el id no es uuid, para no provocar un error de Postgres.
  - `UsersService`, exportado como API pública del módulo.
- **`common/auth`:**
  - `JwtAuthGuard` lee la cookie `access_token` y delega la validación en la interfaz `SessionResolver` (token `SESSION_RESOLVER`), así el guard de `common/` no importa nada interno de otros módulos. Sin sesión válida → `AppError('UNAUTHENTICATED')`.
  - `RolesGuard` usa el rol del usuario releído de la base → `AppError('FORBIDDEN')`.
  - Decoradores `@Public()`, `@Roles()` y `@CurrentUser()`; el tipo de `req.user` está en `common/types/express.d.ts`.
- **Módulo `auth`:**
  - `POST /auth/login` (`@Public`, 200 con `User` y cookie `access_token`), `POST /auth/logout` (204, `clearCookie`) y `GET /auth/me`.
  - `AuthService` implementa `SessionResolver`: verifica el JWT (HS256, `JWT_SECRET`) y relee el usuario en cada petición; si no existe o está inactivo, `null` (RN-14).
  - El JWT lleva solo `sub` y `role` (`iat` y `exp` los agrega la librería) y dura `JWT_EXPIRES_IN` sin renovación (RN-19).
  - Cookie `HttpOnly; SameSite=Strict; Path=/api` con `Expires` igual al vencimiento del JWT.
  - **Login fallido:** credenciales incorrectas, correo inexistente o usuario inactivo dan el mismo 401 `INVALID_CREDENTIALS` "Correo o contraseña incorrectos.". Si el correo no existe se compara igual contra un hash bcrypt de relleno, para que el tiempo de respuesta no delate si la cuenta existe.
  - Login correcto y fallido quedan en los logs de pino (S-02), sin correo, contraseña ni token.
- **Guards globales:** se registran como `APP_GUARD` en `AuthModule`, primero el de sesión y luego el de rol (401 antes que 403, D-32). `@Public()` solo en `POST /auth/login` y `GET /health`.
- **Swagger:** `configureApp()` lo monta solo si `NODE_ENV !== 'production'` (D-33) y declara la cookie de sesión (`addCookieAuth`).
- **Pruebas:** `test/auth.spec.ts`, por HTTP con `fetch`, con un repositorio de usuarios en memoria (`overrideProvider(USERS_REPOSITORY)`) y un controlador de prueba para CA7.

## 6. Desvíos del plan
- **Sin passport:** el backlog menciona una "estrategia JWT". Se usó `@nestjs/jwt` con un guard propio, en lugar de `@nestjs/passport` + `passport` + `passport-jwt`: tres dependencias menos y el mismo comportamiento.
- **`JwtAuthGuard` depende de la interfaz `SessionResolver`** (token en `common/auth/session.ts`), que implementa `AuthService`. Así se cumple que lo transversal vive en `common/` sin que `common/` importe archivos internos de `modules/auth`. Los guards se registran como `APP_GUARD` en `AuthModule`.
- **CA4 contra la base real** con `UPDATE` directo por `psql` (reactivando al final), además del test en memoria.

## 7. Ambigüedades encontradas
- **Rol para `@Roles()`:** el JWT lleva `role`, pero el guard usa el rol **releído de la base** en cada petición. Opción conservadora: si RRHH cambia el rol, aplica en la siguiente petición sin esperar a que venza el token.
- **Validación del body de login:** `email` con `@IsEmail()` y `password` string no vacía. Un correo mal formado da 400 `VALIDATION_ERROR`, no 401 (D-32: el 400 de formato va antes). El correo se normaliza a minúsculas antes de buscar (RN-23).
- **`Expires` de la cookie:** el spec no lo fija. Se usa el vencimiento del JWT, así el navegador la descarta a la vez que el token.
- **Logs del login (S-02):** se registra `event: login` con `result` y, si fue correcto, `userId`. El correo no se registra en los fallidos para no dejar datos personales de intentos ajenos.
- **Rutas inexistentes sin sesión** responden 404 y no 401: Nest resuelve la ruta antes de ejecutar los guards. P-14 habla de las rutas existentes.
